# bazis-uploadable 2.6.0

Requires bazis 2.7.0. Resolves the known limitation of 2.5.0: a user can no longer link the
file of another user to his own object and read it through `include`.

## Access control

- **`FileUploadRouteSet` restricts the files for every route.** The author filter moves
  from `get_queryset` to the classmethod `restrict_queryset(qs, access_action, user=None,
  **kwargs)` of the core `RestrictedQsRouteMixin`, which the route set now inherits; its
  `get_queryset` applies it. As the default route of `uploadable.FileUpload`, it is what
  the core of Bazis 2.7 lets the other routes link and include:
  - a relationship of another model to a file the user did not upload fails with `403`,
    the error code `ERR_RELATION_ACCESS` and the pointer `/data/relationships/<field>`
    (create, update and the relationships endpoints); a link that does not change is not
    checked;
  - `?include=<field>` leaves out the files of other users; the relationship keeps the
    identifier.
- `restrict_queryset` never fails without a user: an anonymous user sees no file; a
  missing user is the authenticated user of the request (`UserMixin.CTX_USER_REQUEST`).

## Breaking changes

- **The attachments of shared objects are no longer included for the other users.** In
  2.5.0 a user read the file of another user through the object that references it
  (`?include=<field>`); now `included` shows only his own files. A project that shares
  attachments widens `restrict_queryset` in a subclass of `FileUploadRouteSet` with
  `default_route = True` (e.g. with the files of the objects the user may read) and
  registers it instead of the bundled router; `AGENTS.md` shows how.
- A subclass that widened `get_queryset` (the pattern of 2.5.0) widens `restrict_queryset`
  instead: otherwise the other routes do not link or include the widened files.

## Upgrading a project

- The route sets of the models that reference uploaded files drop their own ownership
  checks of the files (the `check_attachment` hooks of the sample route set
  `notes.routes.NoteRouteSet` in 2.5.0): the core does the same check. A client that
  matched the error code of such a check gets `ERR_RELATION_ACCESS`.
- A subclass of `FileUploadRouteSet` that also inherits `PermitRouteBase` (listed after
  it) gets both restrictions: `restrict_queryset` of `FileUploadRouteSet` calls the one of
  `PermitRouteBase` through `super()`.
