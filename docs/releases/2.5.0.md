# bazis-uploadable 2.5.0

Requires Bazis 2.4 and bazis-author 2.4 (with bazis-users). Breaking: the uploaded files
have an author and the bundled route set gives a user only his own files.

## Access control

- **New dependency** `bazis-author>=2.4.0` (it needs bazis-users): the project sets
  `BS_AUTH_USER_MODEL` (e.g. `users.User` of `bazis.contrib.users`) and, if it lists
  `BS_BAZIS_APPS`, adds `bazis.contrib.author` and `bazis.contrib.users`.
- `FileUploadAbstract` includes `AuthorMixin`: the fields `author` and `author_updated`. The
  migration `0004_fileupload_author` adds them to `FileUpload`; a model of the project that
  subclasses `FileUploadAbstract` needs a migration (`makemigrations`).
- `FileUploadRouteSet` is based on `AuthorRequiredRouteBase`: a request without a user is
  401; the user who uploads a file becomes its author (a client cannot set it); the list,
  `/_id/` and retrieve give only the files of the user (another user's file is 404); update,
  delete and the relationships endpoints are not served. Before, anyone who reached the API
  listed, read, changed and deleted every file by its sequential id.
- A file of another user (an attachment of a shared object) is read through the object
  that references it (`?include=<field>`), or through a subclass of `FileUploadRouteSet`
  that widens `get_queryset` (see `AGENTS.md`).
- Files uploaded before this version have no author and are shown to no one through the
  route set; a project that needs them in the API assigns their authors with a data
  migration.
- The upload no longer accepts an `id` form field: the id is generated by the server.
- The ids stay integers: changing the primary key to a UUID would rewrite the foreign keys
  of the projects' models to `uploadable.FileUpload`. The access control does not rely on
  unguessable ids.
- The system check `uploadable.W001` (the bundled route set has no access control) is
  removed: the bundled route set is the secure default.

## Serving

- An uploaded HTML page or SVG image runs its scripts when it is opened from the media host.
  An S3 storage of django-storages in `BAZIS_STORAGE_FILE_UPLOAD` (`storages.backends.s3`,
  `s3boto3` or a subclass) gets `S3SafeServingMixin` (`bazis.contrib.uploadable.storages`):
  each object is written with the type of its name instead of the type the client declared
  and, unless it is a raster image, with `Content-Disposition: attachment`.
- `AGENTS.md` and the README describe how to serve the media: a separate origin from the
  frontend and the API, `Content-Disposition: attachment` except raster images,
  `X-Content-Type-Options: nosniff` (an nginx example for the file system storage), and
  that a media URL is readable by anyone who has it (signed URLs for private files).

## Upgrading a project

- A subclass of `FileUploadRouteSet` that only added `UserRequiredRouteBase` and limited
  the actions can drop both: the bundled route set requires a user and serves create, list
  and retrieve. A subclass that emptied the list (`get_queryset_for_list().none()`) can
  drop it: the list gives the user's own files.
- A client that read the files of other users by their ids (a link to an attachment)
  reads them through the referencing resource with `include`, or the project widens
  `get_queryset` of its subclass.
