# bazis-uploadable 2.8.0

Anonymous uploads for public forms (guests attach photos to a request), off by default.
With `BAZIS_FILE_UPLOAD_ANONYMOUS` off the routes behave as in 2.7: the same responses and
the same OpenAPI document.

## Features

- **Anonymous uploads.** `BAZIS_FILE_UPLOAD_ANONYMOUS = True` (with
  `BAZIS_FILE_UPLOAD_MAX_SIZE` > 0) lets a client without a token upload a file through
  `POST /uploadable/file_upload/`, declared `public` in `x-bazis`:
  - only the types of `BAZIS_FILE_UPLOAD_ANONYMOUS_TYPES` (default `image/jpeg`,
    `image/png`, `image/webp`), recognized by the first bytes of the content, not by the
    name or the declared `Content-Type`: another content is 422 `ERR_FILE_TYPE`; the file is
    stored and named with the extension of its type;
  - larger than `BAZIS_FILE_UPLOAD_MAX_SIZE`: 413 `ERR_FILE_TOO_LARGE`, as for the users;
  - `BAZIS_FILE_UPLOAD_ANONYMOUS_RATE` (default `60/hour`) per IP address: 429
    `ERR_THROTTLED` with `Retry-After`; the users who are logged in are not counted;
  - the response has as its id a token (`anonymous_token`: the id of the file signed with
    the time by `SECRET_KEY`, `TimestampSigner`), `name`, `extension` and `size`, not
    `file` (the media URL); the response of a user is unchanged; the file has no author and `uploaded_anonymously` is its time; the guest reads no file
    afterwards (the list, the item and the download stay 401 without a token), and for the
    users it is nobody's (404) until an object references it through `files_visible`.
- **`FileUpload.objects.anonymous(tokens)`**: the anonymous uploads of the valid tokens
  at most `BAZIS_FILE_UPLOAD_ANONYMOUS_TTL` hours old (default 24), of files without an
  author uploaded at most TTL ago: what a public action of a guest attaches to the object
  it creates. A bare id, a forged or expired token and the files of users are never taken.
- **`UploadedFileId`** (`bazis.contrib.uploadable.schemas`): the id an upload answered in
  the body of an action, a string (for a guest his token) whose JSON schema has
  `x-relation: uploadable.file_upload` (`list[UploadedFileId]` has it in `items`), so
  that a client knows the property is a file to upload.
- **`manage.py uploadable_clean_anonymous`** deletes the anonymous uploads older than the
  TTL that no object references (any foreign key, one-to-one or many-to-many field to the
  model of the files, `FileUploadManager.anonymous_expired()`): each row only if it is
  still so when it is deleted, then, once the deletion is committed, its file in the
  storage. A failure of a row or a file is written to stderr, the others are deleted and
  the command exits with an error.
- The clean-up locks a row while it is still expired and not referenced before it deletes
  it: a reference inserted meanwhile waits for the deletion (and fails) instead of being
  set to null by the deletion.
- **Names with a control character** (a NUL, which fails the storage) are 422
  `ERR_FILE_NAME` (`/name`, `/file`) before anything is stored, for the users too.
- **`uploadable.E002`** (`bazis_doctor`): anonymous uploads on without a size limit. Without
  the limit guests upload nothing (the route answers 401), also when the checks are not
  run.
- The settings refuse a type whose signature the package does not know, a rate that is not
  a rate of `bazis.core.throttle` and a TTL below one hour.

## Changes

- The model of the files has the field `uploaded_anonymously` (migration
  `uploadable.0005`), left out of the schemas of the route.
- The upload route takes its user from `upload_user`: the user of the token, an anonymous
  user only when anonymous uploads are on, else the same 401 as before (an invalid token is
  always 401). It always declares the throttle `AnonymousThrottle`, which counts nothing
  for a user.

## Requirements

- Unchanged: bazis 2.16, bazis-author 2.4, bazis-users 2.9 (`public` of the routes and the
  throttles of the core are there since 2.16): anonymous uploads work with bazis 2.16+.
  The OpenAPI document says that the token of the public upload route is optional
  (`security: [{}]`) from bazis 2.21, which declares it for every public route.
- The `test` extra requires bazis-test-utils 2.5.2: its plugin resets the throttle counts
  before each test.

## Upgrading

- Run `migrate` (`uploadable.0005_fileupload_uploaded_anonymously`). A model of the project
  that subclasses `FileUploadAbstract` gets the field too: run `makemigrations`.
- To turn anonymous uploads on: set `BS_BAZIS_FILE_UPLOAD_ANONYMOUS=true` and
  `BS_BAZIS_FILE_UPLOAD_MAX_SIZE`, restart the server (the declaration `public` is read
  when the routes are imported), limit the request body on the reverse proxy for the
  upload path (nginx `client_max_body_size`), let uvicorn or gunicorn trust the proxy
  (`--proxy-headers --forwarded-allow-ips <proxy>`), schedule `uploadable_clean_anonymous`
  and write the public action with `anonymous(tokens)` for a guest (the recipe in the
  guide, section "Anonymous uploads").

## Security notes

- The file of a guest is a valid image by its first bytes only; the rest of the content is
  not checked. It is stored and served with the extension of the recognized type, so the
  media host serves it as an image; serve the media from a separate origin as before.
- The ids of the files are integers (`BigAutoField`): a guest attaches his uploads by
  their signed token, never by an id, so he cannot attach the uploads of other guests.
- The application checks the size after the whole body is received (spooled to disk):
  without the limit of the reverse proxy (nginx `client_max_body_size`) a guest still
  sends bodies of any size; a limit of the core before the body is read is planned for
  bazis 2.21+.
- The rate counts the address uvicorn gives: behind a proxy the proxy sends the address of
  the client (nginx `X-Forwarded-For $remote_addr`) and uvicorn trusts only the proxy
  (`--forwarded-allow-ips`); otherwise all guests share one count, or pick their address.
- Residual risks:
  - Within the TTL the guest who uploaded a file can attach its token again (a token is
    not used up); nobody else has it.
  - The token of a user who is no longer active is a guest when anonymous uploads are on.
  - Changing `SECRET_KEY` invalidates the tokens of the uploads not attached yet, unless
    the old key is kept in `SECRET_KEY_FALLBACKS` (the tokens it signed stay valid).
  - A reference the database does not know (an id in a JSON field, a generic relation)
    does not keep an anonymous upload from `uploadable_clean_anonymous`.

## Why the route set, not a second one

The anonymous upload is a branch of `FileUploadRouteSet.action_create`, the one route of the
resource `uploadable.file_upload`: a second route set of the same resource would give the
frontend two paths of one type (its `ROUTES[type]` keeps one). Four facts shape it:

- `public=True` alone does not admit a guest: the `user` of `AuthorRequiredRouteBase`
  (`get_user_required`) fails the request with 401 before the endpoint. A dependency in the
  signature of a route overrides the field of the same name of the inject classes, so the
  route declares `user=Depends(upload_user)`, which returns an anonymous user only when the
  setting is on and otherwise raises the same 401 at the same step: the other routes of the
  set and the OpenAPI document are unchanged.
- `action_create` of the core answers with `retrieve`, whose queryset is
  `restrict_queryset`: a guest sees no file, so it would be 404 and roll the upload back.
  The anonymous branch answers the created item itself, a JSON:API item whose id is the
  token of the upload and without `file`.
- The ids are integers: the token (`TimestampSigner` with its own salt) makes the id of a
  guest unguessable and expiring without a new field, a migration of the primary key or a
  change of the clients, which send back the id they read.
- A throttle of the route replaces the default one of a public route, and the throttles get
  the user of the route: `AnonymousThrottle` counts only the guests, so the users keep
  their uploads unlimited.

The setting is read per request (the tests switch it), except the declaration `public`,
which is fixed when the routes are imported.
